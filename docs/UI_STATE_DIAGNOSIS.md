# 设置开关状态诊断

2026-10-15，用户报告设置中的开关均无可见变化，包含后台模式与图片背景。

## 证据与根因

- 实机截图 `evidence/matebook-after-tab-click2-20261015.png` 中，后台状态已显示 `dataTransfer` 运行，但两个模式开关仍显示关闭。这证明不能把问题一概归因于后台 API 启动失败。
- `UsbArcSettings.PreferenceRow` 使用四个按值参数的 `@Builder`，开关值通过参数传入。ArkUI V1 的 Builder 按值参数不会随父级状态变化刷新，多参数形式也不构成按引用传递。此处与所有开关共享故障相符。
- `UsbArcController.updatePreferences` 原先还会等待自动授权/共享策略完成，可能使保存后的界面长时间维持忙碌；该流程已拆分为持久化发布和独立串行策略队列。
- `Index.Metric(value, label)` 同样使用多参数 Builder，动态计数存在相同刷新风险。

## 修复与验证要求

设置行与统计项改用真正响应状态的组件或单参数引用形式。后台启动失败应显示真实错误；系统已授权的设备不再显示“请求系统授权”按钮。显式重新启用自动授权时允许重试一次，普通刷新继续去重，避免反复弹窗。

必须在新安装版本验证普通开关开/关、后台两模式、图片选择/启用/关闭、返回页面与重启后的持久化。截图与代码审查不代替这些交互检查。当前记录为修复中，尚未声称实机复验通过。

## 后续实机反馈

拆分组件后，截图已能显示开关变化及生效的图片背景，但不能据此宣布全部问题解决。用户继续反馈整页变灰、开关回弹和跨页状态异常；其中整页禁用来自共享 `busy`，后续改为局部等待与按字段保存队列。字段意图必须在队列执行时与最新偏好合并，旧全量快照不能覆盖更晚操作。

设备卡也存在以固定 ID 缓存普通对象参数的刷新风险。修复应使用正确的观察模型或仅对可见状态变化生成确定的 revision key，禁止每次刷新使用随机 key 导致整页卡片闪烁。最终验收包含停止共享后的卡片、统计及实际占用同步。

本轮代码审查另发现后台任务与普通设置分别保存整份偏好，异步完成顺序可能覆盖对方的新值。修复要求在控制器统一串行持久化，并在执行时只合并本次修改字段；系统后台任务申请及 USB 授权等待必须在短持久化队列之外。验收应包含后台任务申请过程中改变主题/共享范围，而不只是逐个慢速点击。

2026-10-16 继续修复：普通偏好开关即时更新、保持可点击，只在对应行显示保存进度；后台系统任务等待时仅锁定互斥模式开关并提示稍等。控制器已统一字段合并写入，空的 backend 配置变更直接返回，主题/图片等非设备策略保存不再广播 USB 状态或触发自动设备策略。原空配置广播会间接执行至少三次同步 `usbManager.getDevices()`，这是与保存主题无关的额外主线程 IPC。该性能短路需随最终安装包验证，不以较早预览包代替。

停止服务后的设备策略必须以实际接口占用为准：默认释放全部设备，可选保留占用；共享选择可以保留供下次启动恢复，但服务停止时共享计数应为零。卡片需区分空闲、本机占用、共享中、客户端使用中和正在释放，不能仅依据已选共享字段显示正在共享。IPv6 监听也必须由实际 socket 地址族、端口及双栈选项确认，界面文案不能代替连接验证。
